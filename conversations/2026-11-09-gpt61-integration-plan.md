## Model and resource protocol

- Use the locally authenticated Codex CLI with `gpt-6.1-sol` for every new language-model decision. `gpt-6-sol` is an optional fixed-subset sensitivity run, not a substitute for the primary run. Deterministic retrieval, embeddings, arithmetic and evaluation remain Python methods rather than GPT calls.
- The ten-company compatibility run completed all three extraction types: 10/10 general, 10/10 sector and 10/10 SIC2 profiles. This verifies execution and schema compatibility, not factual accuracy. Thirty calls used approximately 623k input and 25k output tokens. Full one-company-per-call inference would be wasteful; implement checked batches grouped by common schema, cap workers at two, record usage and resume by model/prompt/input hash. First validate a small batched run against the current single-company outputs, then expand to 533.
- Reuse the merged `holdout_batched_routes.py`, `check_prompt_versions.py`, `seed_from_v0.py` and saved run manifests for batching, prompt fingerprints and source provenance. Preserve Matthew and Richard's matched Haiku/Sonnet experiments as a baseline; a GPT-6.1 Sol comparison changes only one declared variable at a time.
- A one-query Codex CLI probe with `standalone_web_search` produced an actual `web_search` event and an official source URL. Because that feature is experimental, verify it again in the agent-loop adapter and keep saved-site retrieval as the fallback. Do not depend on a Claude CLI or an unverified OpenAI API balance.

**Error analysis** is a stage-by-stage diagnosis of wrong or missing final answers. For each target it records the earliest *verified* failure when one can be established: wrong company identity or stale business scope; unsupported/missing facet; good peer absent from ranked candidates; good peer discarded or bad peer accepted; missing/misaligned financial data or unstable multiple; or growth-event timing/extraction error. Each row carries the source reference, method version, label cohort and downstream effect. Unverified flags remain hypotheses. This is part of the result, not another peer-selection algorithm.

## Execution amendment — 2026-11-10

The extraction pilot showed that a batched prompt would change the teammate's one-company source and citation protocol. General, Fiona sector and Barbara SIC2 facets therefore retain their exact one-company schemas and run with at most two calls in each extraction stage. The cited-only and Orbis-aligned alternatives have their own exact prompt and input fingerprints. Batching is used only for the direct-selector and binary-judge holdout routes, where the merged route script already defines and checks independent target answers. This replaces the proposed batch extraction optimization; it does not omit any facet family or evaluation.
