# 2026-10-24: v0 steps 1-3 (universe, EV/EBITDA range, facets)

## Why

The mentor's "Recipe for getting comps" (received 2026-10-24) is now the
method. This session built its first three steps in v0/ (first as `comps/`,
renamed during the reorg, see 2026-10-24-pre-v0-reorg.md): the candidate
universe, the EV/EBITDA 3-30 filter, and the facets an LLM fills.

## What changed

- `v0/universe.py`: steps 1-2. The universe is the 560 list itself (decided:
  no EDGAR or Capital IQ pull). All 560 are US-HQ, 43 SIC2 codes; 27 drop
  outside EV/EBITDA 3-30 (20 above, 7 below), 533 remain, all 43 codes still
  covered. Financials split into their own table on load.
- `v0/facets.py`: twelve facets F1-F12 defined once (prompt, answer schema,
  checks). Text facets, and category facets with a fixed category list plus a
  short detail ("B2B: mechanical contractors"). Each facet records its source.
  Company size (F9) is words only: the schema forbids digits, "$" and "%",
  and spelled-out quantities are flagged. Facet guide in plain English.
- Design changes during the session, in order (prompt versions a-f):
  a: model read masked website text only, separate tags field;
  b: example values, categories as the value;
  c: category + detail, source URLs per facet, company size from the website;
  d: company size words-only text, revenue band removed entirely;
  e: model knowledge first (name + website given, no masking), pages optional
     (`--with-pages`), source = model knowledge / website / both;
  f: one profile per business for unrelated businesses (B1 largest, at most
     4); "unknown" only as a last resort, best description + note instead.
- `v0/fill_facets.py`: Codex runner (name + website by default,
  `--with-pages` adds the saved scrape text). One table row per business.
  Stops cleanly at the Codex usage limit; reruns skip current profiles.
- `v0/masking.py` removed (no longer needed once the model gets the name;
  the original is in pre-v0/scraps/codex_profiles/).
- Notebook `v0/notebooks/comp_universe_and_facets.ipynb`: steps 1-2, the
  facet table and guide, the fill test, results and example profiles.
- AGENTS.md trimmed to working habits (data, outputs, handoff, secrets); it
  states that the method lives in PROJECT_STATE.md and v0/README.md and that
  AGENTS.md doesn't limit new designs. Methodology rules removed from it.
- README, data dictionary and PROJECT_STATE updated.

## Results

under the website-only design, or unusable sites) + 18 random (seed 0) +
Ingles Markets (likely multi-business).
- Website-only design (version a, 137 companies): F1 100%, F2 97%, F3 93%,
  F4 96%, F5 99%; F11 61%, F12 64%; 20 universe sites have under 40 words.
- Model knowledge (version e): 99.7% of 360 facets on 30 companies; one
  unknown (Huron, products). With the saved pages, the 12: 99.3% (Crawford,
  products); pages added quotes but not fill.
- Version f: 21 of 31 done before the Codex usage limit, 100% filled, no
  company split. Huron, Ingles and St. Joe (the split test cases) are among
  the 10 not yet run.
- Codex: ~20 s and ~17k input tokens per knowledge-only call, of which our
  prompt is ~1.5k; the rest is Codex's own overhead per call. About 200 calls
  fit in the account's usage window today.
